# Crypto Cash Hunter v3

Мониторинг публичных криптоновостей, условий акций и рынка. Открывай [последнюю сводку](reports/LATEST.md) для TOP-5 новых публикаций. [Подробный HTML](reports/LATEST.html) можно скачать и открыть в браузере. [JSON](reports/latest.json) содержит ту же выборку для программной обработки.

Бюджет €0. Базовый запуск использует Python 3.11+ и стандартную библиотеку. Все интеграции работают на чтение, единственная опциональная отправка — личная Telegram-сводка. Агент не подключает кошелёк, не подписывает транзакции, не выполняет задания и не выставляет ордера. Фактически заработано агентом $0.

## Запуск

```sh
python -B -m unittest discover -s tests -v
python agent.py
```

На Windows можно использовать `RUN_WINDOWS.bat`. В GitHub открой **Actions → Crypto Auto Agents → Run workflow**. Действующее расписание — 00:17, 06:17, 12:17 и 18:17 UTC. Запуск может задержаться. В публичном репозитории используется обычный Ubuntu runner. Тесты выполняются до сетевого мониторинга. Параллельные запуски одной ветки сериализованы, тайм-аут задания — пять минут. Для сохранения отчёта workflow требуется разрешение Contents: write. [Условия GitHub Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions)

Официальное происхождение проверяется по источнику ленты, домену и допустимому пути ссылки. Промоутер может ошибаться даже в собственной публикации.

Дополнительные источники включаются через **Settings → Secrets and variables → Actions**. Для каждого выбирай только разрешённый бесплатный доступ. Пользовательские сессии и cookies не нужны.

В отчёте появляются публичная статья и название площадки. Тела сообщений, авторы, профили, вложения, приватные каналы и контактные данные пользователей соцсетей не экспортируются. Закрытые источники в этой версии отключены. HTTP 403/429 и ограничения платформ не обходятся.

Для **уведомлений** используются отдельные secrets `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Без этой пары сводка сохраняется локально и в Actions. Не записывай токены, ключи или идентификатор личного чата в файлы.

## Telegram — подключение папки «Крипта» и уведомлений

**Локальный сканер.** Нужны Python 3.11+ и собственные API ID и API hash из раздела API development tools на my.telegram.org. В Telegram открой настройки папок и проверь точное имя «Крипта». Каналы, добавленные в эту папку, выбираются по составу папки, в том числе когда в их названии нет слова «крипта». [Регистрация приложения](https://my.telegram.org/) · [Авторизация Telethon](https://docs.telethon.dev/en/stable/basic/signing-in.html)

На Windows выполни в PowerShell из корня проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r local_telegram/requirements.txt
.\.venv\Scripts\python.exe -m local_telegram.scanner --login --folder "Крипта" --show-chat-id
```

Введи API ID, hash, номер, код Telegram и при необходимости пароль 2FA в локальных скрытых приглашениях. Опция `--show-chat-id` однократно покажет твой собственный числовой ID для настройки бота. Для повторного запуска опусти `--login` и `--show-chat-id`. Файл сессии даёт доступ к аккаунту. На Windows он находится в `%LOCALAPPDATA%\CryptoIntelligence\telegram`, на Linux по умолчанию в `~/.local/share/CryptoIntelligence/telegram`. Используй личную учётную запись ОС и диск с шифрованием. При утрате устройства отзови сессию в Telegram → Настройки → Устройства. [Хранение сессий Telethon](https://docs.telethon.dev/en/stable/concepts/sessions.html)

В обычной папке клиент запрашивает список папок и сведения о включённых каналах. Он читает до 30 последних сообщений каждого доступного публичного вещательного канала и пропускает группы, закрытые каналы, защищённые и пересланные записи. В папке с автоматической категорией «Каналы» учитываются исключённые каналы, архив и прочитанность. Для динамического фильтра с исключением по звуку сканер останавливается. При отсутствии папки или совпадении нескольких имён он также останавливается. Опция `--topics` отдельно включает поиск по ключевым словам в названиях подписок. В этом режиме и для динамической категории Telegram возвращает список диалогов, который может содержать превью. Сканер не анализирует эти превью, не запрашивает историю личных диалогов, контакты или участников групп.

**Запуск агента со снимком папки.** Сканер записывает канонические ссылки поддерживаемых источников и агрегированные счётчики в локальный `public-links.json`. Для каждого нового отчёта последовательно выполни:

```powershell
.\.venv\Scripts\python.exe -m local_telegram.scanner --folder "Крипта"
if ($LASTEXITCODE -ne 0) { throw 'Сканирование не завершилось' }
$env:TELEGRAM_SCAN_PATH = Join-Path $env:LOCALAPPDATA 'CryptoIntelligence\telegram\public-links.json'
.\.venv\Scripts\python.exe agent.py
```

Агент принимает снимки за последние сутки и сопоставляет ссылки с публичными публикациями. Детектор проверяет установленную пару сеть/адрес, а HTML и JSON содержат условия, источники и шаги для ручной проверки или участия. Неподтверждённые условия, сомнительный контракт и явные ограничения отображаются в списке препятствий. Автоматическое получение наград отключено.

**Бот уведомлений.** Открой личный чат с @CryptoHunterBotai и нажми Start. Если бот принадлежит тебе, получи его токен у @BotFather. Для сводки из GitHub Actions добавь `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в Settings → Secrets and variables → Actions → Repository secrets. Первый секрет содержит токен бота, второй — числовой ID твоего личного чата. Перед отправкой агент проверяет имя бота через getMe. Проверь результат запуска в разделе доступности источников и по доставке в личный чат. [Бот](https://t.me/CryptoHunterBotai) · [Настройки secrets](https://github.com/Syslik667/crypto-auto-agents/settings/secrets/actions)

Для уведомлений **с учётом папки** передай эти же две переменные локальному процессу `agent.py` из хранилища секретов ОС. Секреты GitHub доступны только облачному запуску. В Actions по желанию можно отдельно указать токен бота чтения `TELEGRAM_SOURCE_BOT_TOKEN` и до пяти публичных username в variable `TELEGRAM_PUBLIC_CHANNELS` через запятую. Поддерживается прежняя настройка одного канала. Этот источник читает закрепления.

**Круглосуточный режим.** На постоянно включённой доверенной машине используй отдельную учётную запись ОС и локальную копию репозитория. Пройди интерактивный вход один раз. Планировщиком запускай сканер, затем при успехе агент из той же копии, например раз в шесть часов без пересечения запусков. Передавай `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и переменные бота из защищённого локального хранилища. На Linux укажи `TELEGRAM_SCAN_PATH=$HOME/.local/share/CryptoIntelligence/telegram/public-links.json`. Храни папку сессии вне Git, облачной синхронизации и артефактов CI. Облачный workflow использует публичные источники и Bot API. MTProto-клиент блокирует запуск в GitHub Actions до создания сессии.

## Airdrop Hunter

Публикации объединяются по каноническому URL. Сообщение каталога может объединиться с однозначно связанным официальным промоанонсом. Совпадения тикера или заголовка недостаточно. При обновлении с v1 учитываются прежние хэши. Каждая карточка показывает происхождение и заявленные условия участия, депозит, сетевые комиссии, KYC, Германию, срок и вывод. Парсер распознаёт явные англоязычные формулировки. «Не указано» требует ручной проверки. Даже заявление о выводе не подтверждает получение средств. XP, points и waitlist отражаются отдельно от денежных выплат.

В сводку попадают до пяти впервые замеченных публикаций за последние 14 дней. Сначала учитываются официальный источник, число известных условий, упоминание в соцканале и явное заявление об отсутствии депозита. При равенстве решают дата и URL. В полном отчёте остаются и исключённые находки с указанием причины, в том числе просроченные акции, известные обязательные затраты, исключение Германии, ограниченный вывод и высокий риск. Пункты с неизвестными условиями могут появиться в TOP для ручного изучения.

## Scam Detector

Единица анализа — пара из идентификатора сети и адреса контракта. Поддержаны Ethereum (1), Base (8453) и Arbitrum (42161). Сначала проверяются контракты из [watchlist.json](watchlist.json), затем явно указанные в официальной публикации, например `Ethereum contract: 0x…`. Адрес без сети или неоднозначное упоминание остаётся непроверенным. Публикация на официальном домене не подтверждает произвольные внешние claim-сайты.

| Источник | Что проверяется |
|---|---|
| [GoPlus](https://docs.gopluslabs.io/reference/response-details) | Признаки honeypot, ограничения продажи, налог, эмиссия, прокси, управление балансами, блокировки, доля крупнейшего адреса в выборке держателей |
| [DEX Screener](https://docs.dexscreener.com/api/reference) | Максимальная USD-ликвидность наблюдаемого пула, где совпадают и сеть, и один из адресов токенов |
| [DeFiLlama](https://api-docs.defillama.com/) | Наличие справочной цены именно для данной пары сеть/адрес |
| [Chainabuse](https://docs.chainabuse.com/reference/reports-1) | При наличии бесплатного secret `CHAINABUSE_API_KEY` для Ethereum проверяется наличие публичной жалобы. Ответы с персональными данными не сохраняются |

**Высокий риск** — признаки honeypot, ограничения продажи, изменения чужих балансов или налог продажи от 50%. **Требует проверки** — другие рискованные полномочия, налог выше 10%, жалоба, наблюдаемая доля одного адреса от 20% либо крупнейший пул меньше $25 000. Пулы и биржевые адреса также могут быть крупными держателями. **Недостаточно данных** — обязательная часть проверки отсутствует и явных флагов не обнаружено. **Низкий обнаруженный риск** — проверки дали достаточно данных без отмеченных признаков. Отсутствие тревожных сигналов не гарантирует безопасность. Пороги — эвристики проекта. У каждой оценки указаны причины и источники.

За запуск проверяются до четырёх различных контрактов. Локальный лимит Chainabuse — десять попыток за календарный месяц UTC, до одной попытки на адрес за месяц. Отказ тоже расходует попытку. В истории сохраняются месяц и признаки наличия жалоб. Для ключа, используемого другими приложениями, остаток внешней квоты может быть меньше. [Лимиты Chainabuse](https://docs.chainabuse.com/docs/getting-started-2-1)

## Состояние и сбои

Сетевые запросы ограничены по времени и объёму. При HTTP 403, 429 или Retry-After оставшиеся обращения к этому хосту пропускаются до следующего запуска. Ошибка одного источника отражается в HTML и JSON. Если одновременно недоступны рынок и все ленты, Actions показывает ошибку и сохраняет предыдущие отчёты и историю с их исходной датой. Число совпадений в соцсетях относится только к доступной выборке.

`data/seen.json` содержит историю до 6000 недавно наблюдавшихся идентификаторов и компактный месячный кэш Chainabuse. Отчёты заменяются через временные файлы, история обновляется после них. Повреждённая история останавливает запуск, чтобы ранее учтённые публикации не стали новыми. Workflow коммитит только три отчёта и этот файл состояния.

GitHub Actions выполняет по одному запуску на ветку. После ожидания в очереди сканирование начинается с актуальной версии ветки. Если кто-то отправит коммит во время сканирования, шаг `Save reports` сохранит обе истории Git, объединит идентификаторы находок и кэш запросов. Из двух комплектов JSON, Markdown и HTML он выберет более свежий по времени отчёта в UTC. При одинаковом времени приоритет у уже опубликованного комплекта. Объединение сохраняет все идентификаторы обеих сторон, поэтому до следующего сканирования их может быть больше 6000.

При очередном изменении ветки шаг повторяет обычный push, максимум три попытки за запуск. Повторная публикация использует уже собранные данные. Если публикация завершится ошибкой, комплект отчётов и история находок будут доступны в артефакте `unpublished-reports-…` этого запуска в течение семи дней.
